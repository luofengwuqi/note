# 删除用户
做一五馄饨时候整的业务.  
删除 不光要删除用户还要删除用户关联的表(点赞/各种记录/等等...)  
解决方案:  

1. 单体项目(小项目):
直接开一个事务 然后在UserServiceImpl里面堆料就行了  
高级的堆料:  
```yml
# 用户关联附属表（软删除统一配置）
user:
  related-tables:
    - user_detail    # 用户详情
    - user_order     # 用户订单
    - user_address   # 用户地址
    - user_collect   # 用户收藏
    # 新增表只在这里加，不用改代码！
```
```java
    // 读取配置的所有关联表名
    @Value("${user.related-tables}")
    private List<String> userRelatedTables;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void deleteUserSoft(Long userId) {
        // 🔥 核心：循环所有配置表，批量软删除（一行代码搞定N张表）
        userRelatedTables.forEach(tableName ->
                commonDeleteMapper.softDeleteByUserId(tableName, userId)
        );

        // 最后软删除用户主表
        userMapper.softDeleteById(userId);
    }
```
```xml
<delete id="softDeleteByUserId">
    UPDATE ${tableName}
    SET is_deleted = 1
    WHERE user_id = #{userId}
</delete>
```

2. 分布式项目(大项目):  
* 安全方面  
不要一点删除按钮整个数据全没了 先**软删除**  
说白了就是给数据库加一个字段is_deleted 如果删了很久也没恢复就彻底删除  
而且有些数据不能乱删 比如订单
* 性能方面  
为了防止超大事务慢的要死 所以要用**异步**
* 设计方面  
**解耦**:你在userService里面写一大堆调用其他模块的方法 太耦合了  
用消息队列(MQ) 发个消息就行 其他人怎么接收 userService不用管
