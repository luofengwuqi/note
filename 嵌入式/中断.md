# 外部中断(EXTI)

## 信号路径
```
GPIO(引脚电平变化) → AFIO(选中断线) → EXTI(边沿检测) → NVIC(优先级仲裁) → CPU(执行中断函数)
GPIO → AFIO → EXTI → 其他外设(事件,不经过CPU)
```
- **NVIC** 帮 CPU 处理中断优先级,不产生中断,只决定"谁先跑"
- 类比:EXTI 是叫号系统,CPU 是医生,NVIC 是分诊台

## 一、一条中断线只能接一个端口(最容易踩的坑)

EXTI 只有 16 条线(Line0~Line15),线号按**引脚编号**对齐:PA0 / PB0 / PC0… 抢的都是 Line0。

AFIO 里有一组 EXTICR 寄存器,决定每条线**当前**挂在哪个端口:

```c
GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource0);   // Line0 ← PB0
```

这条语句一执行:

- PA0 的下降沿**不再**产生中断请求,哪怕 GPIOA 那边配得好好的
- 是"改接",不是"新增",**没有任何报错或提示**
- 谁最后调用谁生效,调试时表现为"昨天还能用的按键今天不动了"

真实案例:按键原本在 PA0(Line0) → 后来编码器 A 相接 PB0(Line0) → 按键中断静默失效。
这就是江科大教程里按键用 **PB14**、编码器用 **PB0/PB1** 的原因:14 和 0/1 不撞线。

## 二、中断通道不是"一条线一个"

| 线号 | 中断通道(`NVIC_IRQChannel`) | 服务函数名 |
|---|---|---|
| Line0 | `EXTI0_IRQn` | `EXTI0_IRQHandler` |
| Line1 | `EXTI1_IRQn` | `EXTI1_IRQHandler` |
| Line2 | `EXTI2_IRQn` | `EXTI2_IRQHandler` |
| Line3 | `EXTI3_IRQn` | `EXTI3_IRQHandler` |
| Line4 | `EXTI4_IRQn` | `EXTI4_IRQHandler` |
| Line5~9 | `EXTI9_5_IRQn` | `EXTI9_5_IRQHandler` |
| Line10~15 | `EXTI15_10_IRQn` | `EXTI15_10_IRQHandler` |

- 0~4 号线各自独占一个通道,5~9 共用、10~15 共用 → **共用一个函数,进去必须自己判断是哪条线**
- 函数名由 `startup_stm32f10x_md.s` 的向量表写死,**拼错不报错,只是永远不执行**
- 常见错配:`EXTI_Line0` 却配 `EXTI15_10_IRQn`,或 `EXTI_Line4` 配 `EXTI2_IRQn`(应该是 `EXTI4_IRQn`)

## 三、初始化五步(以按键 PA0 为例)

1. **开时钟**:`GPIOA` + `AFIO`(EXTI/NVIC 时钟默认自动开启,不用管)
2. **配引脚**:上拉输入 `GPIO_Mode_IPU`(按键一端接 GND,松开为高,按下为低)
3. **AFIO 选线**:`GPIO_EXTILineConfig(GPIO_PortSourceGPIOA, GPIO_PinSource0)`
4. **配 EXTI**:`EXTI_Line0` + `EXTI_Mode_Interrupt`(中断模式,不是事件模式) + `EXTI_Trigger_Falling`(下降沿)
5. **配 NVIC**:优先级分组 2(2 位抢占 + 2 位子优先级),抢占 1、子 1

```c
void CountSensor_Init(void)
{
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);   //1. GPIOA 时钟
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO,  ENABLE);   //   AFIO 时钟

	GPIO_InitTypeDef obj = { 0 };                            //2. 引脚
	obj.GPIO_Pin   = GPIO_Pin_0;
	obj.GPIO_Mode  = GPIO_Mode_IPU;       // 上拉输入
	obj.GPIO_Speed = GPIO_Speed_2MHz;     // 输入模式下速度无实际意义
	GPIO_Init(GPIOA, &obj);

	GPIO_EXTILineConfig(GPIO_PortSourceGPIOA, GPIO_PinSource0);  //3. 选线

	EXTI_InitTypeDef extiObj = { 0 };                        //4. EXTI
	extiObj.EXTI_Line    = EXTI_Line0;
	extiObj.EXTI_LineCmd = ENABLE;
	extiObj.EXTI_Mode    = EXTI_Mode_Interrupt;
	extiObj.EXTI_Trigger = EXTI_Trigger_Falling;             // 下降沿
	EXTI_Init(&extiObj);

	NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);          //5. NVIC
	NVIC_InitTypeDef nvicObj = { 0 };
	nvicObj.NVIC_IRQChannel                   = EXTI0_IRQn;
	nvicObj.NVIC_IRQChannelCmd                = ENABLE;
	nvicObj.NVIC_IRQChannelPreemptionPriority = 1;
	nvicObj.NVIC_IRQChannelSubPriority        = 1;
	NVIC_Init(&nvicObj);
}
```

> 多个通道时 `NVIC_Init` 要调用多次,改结构体里的 `NVIC_IRQChannel` 再调一次即可(见后面编码器的例子)。

## 四、中断服务函数:三步法

```c
void EXTI0_IRQHandler(void)
{
	if (EXTI_GetITStatus(EXTI_Line0) == SET)                 // 1. 验身份
	{
		Delay(20);                                            // 2. 消抖
		if (GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0) == 0)     //    复查电平
			Count_++;                                         //    真按下才计数
		EXTI_ClearITPendingBit(EXTI_Line0);                   // 3. 清标志(必须)
	}
}
```

- **验身份**:共用的向量(如 `EXTI15_10`)里必须判断是哪条线;独占向量里也建议保留,养成习惯
- **清标志必须在最后**:这 20ms 里若又有抖动,挂起位会被重新置位;提前清会导致立刻再进中断
- 不清就会退出后马上又进来,表现像死循环卡死

## 五、数据共享

```c
volatile uint16_t Count_;                 // 中断里 ++,主循环里读
uint16_t getCount_(void){ return Count_; }
```

- 中断和主循环共享的变量要加 `volatile`,否则优化后主循环可能一直读寄存器里的旧值
- `uint16_t` 在 32 位机上是单条指令读写,不会读到"改了一半"的值;`uint64_t` 就会,需要关中断保护
- 计数要能显示负数(编码器左转)时改成 `int16_t`/`int32_t`,显示函数也要换成 `OLED_ShowSignedNum`

## 六、消抖:三种做法,按场合选

| 做法 | 实现 | 适合 | 代价 |
|---|---|---|---|
| 阻塞延时 + 复判 | 中断里 `Delay(20)` 再读电平 | 按键 | 20ms 内 CPU 被占死 |
| 只复判电平 | 中断里立刻再读一次引脚 | 编码器 | 只能滤掉极短毛刺 |
| 时间戳非阻塞 | `GetTick() - last > 20` 才认 | 高频/低功耗/要流畅 | 需要一个毫秒时基 |

**为什么编码器不能用 `Delay`**:转一格可能只有几毫秒,20ms 的阻塞延时会把后面的脉冲全部吞掉,转得越快丢得越多。所以编码器只在中断里"再读一次电平"做最基本的去毛刺,靠硬件和布线保证信号干净。

## 七、在中断里调 `Delay` 的前提条件

`delay.c` 里的 `Delay()` 靠 `ulTicks` 累加(在 `SysTick_Handler` 里 `ulTicks++`)。

如果 **SysTick 的优先级低于当前 ISR**,它无法抢占正在执行的中断,`ulTicks` 永远不增长 → `while(ulTicks < expiredTime)` 死等 → **程序卡在中断里出不来**。

本项目能用的原因:`Delay_Init()` 里有一句

```c
SCB->SHP[7] = 0;      // 把 SysTick 设成最高优先级 0
```

而 EXTI 的抢占优先级是 1,所以 SysTick 能抢占它,计时照常走。

> 换别的延时库(尤其是靠 `for` 空转或用别的定时器的)之前,先确认这一条,否则中断里一调就死机。

## 八、实战:旋转编码器(增量式正交编码器)

### 8.1 硬件

- EC11 类编码器,A、B 两相输出**相差 90° 的方波**,内部就是两组机械触点
- 只有 A 相只能知道"在转";加上 B 相才能靠**谁先跳变**判断方向,这就是正交解码
- **4 脚裸编码器**:`A / B / C + 按键两脚`,**C 是公共端,必须接 GND**
- **5 脚模块(VCC/GND/A/B/C)**:公共端在板内已接 GND,**C 是按键输出**,按下输出低电平(DFRobot SEN0235 同款)

### 8.2 判向原理

A 出现下降沿的那一刻,读 B 的电平:

- B 还是低 → 一个方向
- B 是高 → 另一个方向

B 出现下降沿时同理,读 A。

### 8.3 代码(PB0=A 相,PB1=B 相)

```c
int16_t count;                            // 有符号:左转要能减到负数

void CountSensor_Init(void)
{
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO,  ENABLE);

	GPIO_InitTypeDef obj = { 0 };
	obj.GPIO_Pin   = GPIO_Pin_0 | GPIO_Pin_1;   // 两相一起配
	obj.GPIO_Mode  = GPIO_Mode_IPU;             // 上拉输入
	obj.GPIO_Speed = GPIO_Speed_2MHz;
	GPIO_Init(GPIOB, &obj);

	GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource0);   // Line0 ← PB0
	GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource1);   // Line1 ← PB1

	EXTI_InitTypeDef extiObj = { 0 };
	extiObj.EXTI_Line    = EXTI_Line0 | EXTI_Line1;
	extiObj.EXTI_LineCmd = ENABLE;
	extiObj.EXTI_Mode    = EXTI_Mode_Interrupt;
	extiObj.EXTI_Trigger = EXTI_Trigger_Falling;      // 只关心下降沿
	EXTI_Init(&extiObj);

	NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);

	NVIC_InitTypeDef nvicObj = { 0 };
	nvicObj.NVIC_IRQChannel                   = EXTI0_IRQn;   // A 相
	nvicObj.NVIC_IRQChannelCmd                = ENABLE;
	nvicObj.NVIC_IRQChannelPreemptionPriority = 1;
	nvicObj.NVIC_IRQChannelSubPriority        = 1;
	NVIC_Init(&nvicObj);

	nvicObj.NVIC_IRQChannel            = EXTI1_IRQn;          // B 相:改通道再初始化一次
	nvicObj.NVIC_IRQChannelSubPriority = 2;
	NVIC_Init(&nvicObj);
}

void EXTI0_IRQHandler(void)                                   // A 相下降沿
{
	if (EXTI_GetITStatus(EXTI_Line0) == SET)
	{
		if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_0) == 0)    // 复判:排除干扰脉冲
		{
			if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0)// 此刻 B 也是低
				count--;
		}
		EXTI_ClearITPendingBit(EXTI_Line0);
	}
}

void EXTI1_IRQHandler(void)                                   // B 相下降沿
{
	if (EXTI_GetITStatus(EXTI_Line1) == SET)
	{
		if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0)
		{
			if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_0) == 0)// 此刻 A 也是低
				count++;
		}
		EXTI_ClearITPendingBit(EXTI_Line1);
	}
}
```

### 8.4 关于"倍频"

一个完整的电周期里 A、B 各下降一次,但**同一周期里只有一个满足"另一相也是低"**,所以这段代码**每格记 1 次**。

- 实测一格跳 2 → 你的型号每格有两个电周期,或程序里改成了双沿触发
- 想更细分辨率,可以改成 `EXTI_Trigger_Rising_Falling` 双边沿 + 状态表,即"4 倍频"(定时器编码器模式默认就是 4 倍频)
- 方向反了(右转变小):把两个函数里的 `count--` 与 `count++` 对调,其他都不用动

## 九、坑清单

| 现象 | 原因 |
|---|---|
| 中断函数永远不执行 | 函数名拼错(必须与向量表一致)、`NVIC_IRQChannelCmd` 没使能、`EXTI_LineCmd` 没 ENABLE、线号与通道号不匹配 |
| 进了中断就出不来 / 疯狂重复进 | 没调 `EXTI_ClearITPendingBit` |
| 按一下加好多次 | 没消抖,或消抖后没复查引脚电平 |
| 某个引脚突然不能触发 | 同号线号的另一个端口把它顶掉了(`GPIO_EXTILineConfig` 是改接不是新增) |
| 编译报 `EXTI1_IRQn` 相关错误 | 通道写成了 `EXTI2_IRQn`,线号与通道要对齐 |
| 计数不涨 / 一直显示旧值 | 变量没加 `volatile`;或改了变量名(如 `Count_`→`count`)而中断里没跟着改 |
| 中断里调 `Delay` 后死机 | SysTick 优先级低于当前 ISR,无法抢占,`ulTicks` 不再增加 |
| 延时突然变得不准、计数乱 | 跨文件 `extern` 的类型和定义不一致(如 `uint64_t` 对 `uint32_t`),自增写坏相邻变量 |
| 编译报 `uint16_t` 未定义 | 驱动头文件没 `#include "stm32f10x.h"`,靠调用方的包含顺序侥幸通过 |

## 十、模块划分

| 文件 | 作用 |
|---|---|
| `CountSensor.c` | 初始化 GPIO/EXTI/NVIC + 中断服务函数 + 计数变量 |
| `CountSensor.h` | 对外只暴露 `CountSensor_Init()` 和 `getCount_()`,并自己 `#include "stm32f10x.h"` |
| `user/main.c` | 调初始化、OLED 显示计数 |

把外设细节从 `main.c` 里抽出来,`main.c` 只关心"拿计数去显示",不关心中断怎么配的。
文件名/函数名最好跟着功能改(编码器就该叫 `Encoder.c` / `Encoder_Init()`),否则半年后自己都看不懂。

`main.c` 里还躺着 `bilnk()` / `shout()` / `init_GPIO()` / `OLED()` 四个旧实验函数,现在都没被调用,建议删掉或注释。

## 十一、main.c(编码器版)

```c
#include "stm32f10x.h"
#include "OLED.h"
#include "../CountSensor.h"          // main.c 在 user/ 子目录,用相对路径

int main(void)
{
	int16_t lastCount;

	CountSensor_Init();
	OLED_Init();
	OLED_ShowString(1, 1, "Count:");              // 固定文字只写一次

	lastCount = getCount_();
	OLED_ShowSignedNum(1, 7, lastCount, 5);       // 第 7 列起,带符号,5 位

	while (1)
	{
		int16_t now = getCount_();
		if (now != lastCount)                     // 变了才刷,避免整屏刷新闪烁
		{
			lastCount = now;
			OLED_ShowSignedNum(1, 7, lastCount, 5);
		}
	}
}
```

- `OLED_ShowNum` 参数是 `uint32_t`,负数会显示成巨大的正数 → 有符号一律用 `OLED_ShowSignedNum`
- 变化才刷新,既省 I2C 带宽也避免闪烁;位数固定,不会留残影

## 十二、可以改进的地方

1. **中断里不要 `Delay`**:改成"中断只置标志位 + 主循环处理",或 `GetTick()` 时间戳判间隔
2. **计数值溢出**:`int16_t` 到 32767 会翻负,长期统计用 `int32_t`
3. **编码器换定时器硬件解码**:PB6/PB7(TIM4)、PA0/PA1(TIM2)、PA6/PA7(TIM3) 可用"编码器模式",硬件自动加减,不占 CPU,也不会丢步——但引脚必须落在 CH1/CH2 上才支持
